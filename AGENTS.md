# Project conventions

- Orphaned-payment warnings use `orphaned-payments` to exclude actual source/recipient split connections, with legacy notes as a fallback; intentionally isolated split records must not be reported as broken reservation links.

- Reservation date expansions are validated by `reservation-edit-limits` in the shared update hook, using freshly read organization-scoped settings and stays; this covers both Edit Booking and Combine Into One Stay without double-counting the original stay.
- Reservation edit policy tests use Bun's test runner because the project has no existing test runner.
- New reservations use `reservation-create-limits` with exact target-year settings and explicit saved turns, re-read in the shared creation hook before saving; this prevents stale forms and used-pick counts from bypassing the Done handoff. Booking previews use a year-scoped snapshot rather than selection hooks with side effects.
- Historical stay settlement uses `stay-settlement` over each person's full chronological ledger, independent of year filters, without rewriting closing balances; later charges must not reopen debt already settled.
- Incoming transfers use `transfer-balance` to consume existing debt before adding surplus to forward-credit pools; latest-stay actions use the final personal balance while historical closing balances remain unchanged, preventing duplicate credit use.
- Primary-to-secondary handoff uses exact target-year settings and fresh explicit completion records, activates reverse rotation idempotently, and refreshes phase state; this prevents stale usage or unstarted status rows from blocking the last primary family's secondary pick.
- Family role resolution prioritizes organization-scoped claimed profiles and saved account links before legacy email/name matching; shared resolution keeps direct login and read-only impersonation consistent without changing contact or login emails.
- SecondarySelectionManager receives the calendar's selection year and loads exact-year settings, usage, and status; independent date calculations must not split the banner from booking eligibility.
- Selection-year data hooks discard stale-year responses and phase detection retries failed reads rather than falling back to Round 1.
- Selection banners/status use `useSelectionUsageDisplay` for read-only scoped refreshes, never booking reconciliation; booking success and explicit Done emit a shared display-refresh event so independent counters refresh together without advancing turns.
- Status dates use the pure `selection-display-schedule` projection from saved active dates and extensions; waiting estimates are never persisted, preventing display changes from rewriting active seasons.
- Selection-turn notification completion uses the saved active round and current secondary family, never primary completion during secondary selection; skipped or failed sends must not be recorded as delivered.
- Post-rotation settings always edit the active selection season (getSelectionRotationYear), never the rotation anchor year; the last Round 2 finish schedules the opening immediately via `schedule-free-selection`.
- Free selection after both rounds uses `post-rotation-hold` (`freeSelectionState`) in the shared booking check, the calendar status, and the daily checker (copy in `functions/_shared`); hold settings save only their own columns so active-season setup is never re-saved, and announcement/reminder timestamps are written only after a successful send.
- The post-booking "Are you done selecting?" prompt only points to the I'm Done Selecting button; it never ends a turn itself, keeping handoff an explicit family action.
- Calendar and reminder completion reads use `selection-round-completion`: legacy Done is primary-only, bookings never imply Done, and wrong-year records fail closed; the external additive fields and compatibility triggers are confirmed installed.
- Secondary handoffs re-read scoped completion and guard the saved outgoing family/start timestamp; its database trigger records Done atomically, preventing stale/repeated handoffs and allocation-based skips.
- The turn-notification sender owns primary and secondary successful-delivery tracking; both immediate and scheduled paths use it to avoid duplicate history and retries after delivery.
- Usage reconciliation uses `selection-usage-reconciliation` to skip active/finished seasons and write counts only; handoff compatibility triggers must be installed before switching separate-round consumers so outgoing completion and pointer changes share one transaction.
- Season readiness uses `selection-preflight` as a pure projection over already-loaded, organization-scoped rows; the readiness card and `useSelectionPreflight` only read, so a failing check is reported for a human to fix and never repairs selection state on its own.
- Yearly season-setup reminders use the pure `_shared/season-setup-reminders` decision inside `auto-create-selection-season`, which runs automatic setup before reminders and logs delivery per season in notification_log; this prevents duplicate or pointless reminders.
